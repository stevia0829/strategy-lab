# Strategy IR v1 与统一执行规范

这份规范约束两套独立实现。修复语义时必须同时修改 Go、Python，并添加能够区分错误行为的测试。跨语言结果一致仍有可能共享概念错误，因此需要手算黄金样例。

## 1. 配置与验证

顶层必需字段：`version=1, name, universe, benchmark, indicators, entry, exit, selection, execution`。可选 `start/end` 为包含端点的 ISO 日期。未知字段、重复资产、未知指标引用、非有限数和非法参数必须拒绝。最多 100 只候选、40 个指标、规则嵌套 8 层、每组 20 个条件。

原始字段是 `open/high/low/close/volume`。指标别名不得覆盖这些字段。

规则可以是布尔常量、`all`、`any`、`not`，或 `{left,op,right}`。左右操作数均可为有限数值或已声明指标引用。允许 `gt/gte/lt/lte/eq/cross_above/cross_below`。不支持 eval、函数调用字符串或隐式未来偏移。

上穿：前一个已观测日 `left <= right`，当日 `left > right`；下穿反之。缺少指标值时得到 unknown，`not unknown` 仍是 unknown，只有 true 才能触发入场/退出。AND 中 false 优先，OR 中 true 优先。

## 2. 指标

所有指标仅依赖当前与过去已观测行情；提前计算完整数组不允许使用未来数据。

| 指标 | 口径与首次可用时间 |
| --- | --- |
| SMA | 最近 N 个观测值简单平均；第 N 根 |
| EMA | 前 N 根 SMA 为种子，之后 `alpha=2/(N+1)`；第 N 根 |
| RSI | N 个价差的涨/跌均值为种子，之后 Wilder 平滑；第 N+1 根。全平为50，无跌有涨为100 |
| MACD | EMA(fast)-EMA(slow)；signal 为该序列的 SMA 种子 EMA；hist=line-signal，**不乘2**。默认12/26/9，hist第34根可用 |
| ROC | `(value[t]/value[t-N]-1)*100`；第 N+1 根，单位百分数 |
| momentum_score | N 根对数价格回归；回归权重为线性1..2的平方，R²权重为一次1..2，年化 `exp(slope*250)-1` 乘 R²；第 N 根 |
| ATR | true range 的 Wilder 平滑，首根 TR=high-low，前 N 根均值为种子；第 N 根 |
| highest / lowest | 最近 N 根最大/最小；第 N 根 |

指标默认字段 close。ATR 使用 OHLC（其 field 参数不参与计算）。价格为零/负数的动量对数不计算；数值溢出产生 unknown，不能当成无限强买入信号。

每个资产按自身真实存在的 bar 计算指标，不为缺失日期补零或造行情。因此周期是已观测 bar 数，跨资产“同一天”通过日期对齐。若研究要求严格连续交易日，应先清洗输入并检查缺失记录。

## 3. 事件顺序与目标选择

1. 回测日历是池中资产及基准日期的有序并集。开始日之前只提供预热历史，不持仓、不累计模拟盈亏。
2. 若开始日前有历史日，在开始日开盘可执行最近历史日收盘的信号；没有历史则第一天不能用自己的收盘价在开盘成交。
3. 每日开盘先执行上一个日历日的卖出计划，再尝试买入。无 bar、volume=0、涨跌停限制触发时拒单并记录原因；不假定成交。
4. 卖出失败的仓位继续占用持仓槽位与资金。失败订单不无限排队，每日按当日收盘可用信号重新生成计划；缺失行情的已有持仓保留。
5. 每日收盘按真实数量估值，记录现金、净值、实际仓位、基准、缺失行情的持仓代码，然后形成次日目标。
6. 最后一天只形成下一日目标，不执行窗外订单、不强制平仓；未实现盈亏计入最终净值。

`hold`：已有持仓直到退出规则 true；按排名填补空位，不因新候选评分更高主动换仓。

`rotate`：未触发退出的已有持仓与满足入场的新候选一起排名，选择前 N 个。退出优先，不能同一收盘信号又退出又重入。分数相同按 symbol 字典序，结果不依赖映射遍历顺序。缺失排名值的已有持仓保留。

## 4. 资金与成本

只做多，无融资，每日无隐式再平衡。每个新增仓位的预算不超过：可用现金、开盘总资产×入场仓位上限÷最大持仓数、总风险预算剩余额度三者最小值。

买入价格为 open×(1+slippage)，卖出为 open×(1-slippage)。佣金为 `max(min_commission,成交金额×commission_rate)`；按 lot_size 向下取整，费用不足进一步减少数量。买卖价格已体现滑点，不可在现金中再次扣滑点。

`total_costs` 是已扣佣金加相对开盘价格的滑点成本，便于解释，与会计现金扣款区别处理。资金不够买一手时记录拒单。卖出后资金当天可用于另一只资产；同一仓位的买卖至少跨日，适配日频 T+1 使用方式。

涨跌停字段缺省为 0，表示未建模；开盘 >= limit_up 禁止买入，开盘 <= limit_down 禁止卖出。不模拟集合竞价排队、盘口容量、实际成交量约束与盘中开板。price-volume impact 等模型尚未实现。

已有持仓不会因涨价超过入场仓位上限而自动卖出。研究者可以用退出规则控制风险，但引擎不私自添加移动止损、时间止损或频繁再平衡。

## 5. 净值与统计

- 每个会话：cash + Σquantity×close。持仓当日无 bar 时暂以上一次已知收盘估值，记录 `stale_symbols`；这不是伪造可交易行情。
- 基准：首个回测日开盘至每日收盘的无费率、可分数单位买入持有；基准缺日延续最近收盘，不代表当天真实成交。
- 收益率：最终净值/初始资金−1。年化按实际回测会话数 N 使用 `(final/initial)^(252/N)-1`，不是自然日年化。
- Sharpe：完整日净值收益（含空仓日与成本）均值/样本标准差×sqrt(252)，无风险收益0；标准差0时 null。
- 最大回撤：以初始资金为首个峰值，再逐日更新高水位，包含所有未平仓期间盈亏。
- 最大回撤恢复天数：该次回撤起点峰值至首次重回峰值的会话数；截止未恢复为 null，不能填0。无回撤为0。
- 最长水下天数：连续未重回此前峰值的最大会话数，不含重回峰值当天。因此它可比已恢复回撤的峰值到恢复间隔少1。
- Calmar：年化收益/最大回撤；没有回撤或年化溢出时 null。
- 胜率只统计完整平仓且含佣金与滑点的交易，盈亏为0不算赢；未平仓不进入分母。
- 换手字段 `traded_notional_over_initial`：双边成交金额总和/初始资金，不冒充以平均NAV为分母的年化换手。
- 浮点极端年化溢出以 null 标注，不写 Infinity 或伪造有效数字。
- 对资产池和基准的相邻已有收盘价做异常跳变检查；跌幅超过 35% 或涨幅超过 35% 时在报告中提示核对拆分、合并、分红及复权口径。该提示不修改行情或收益，也不能据此判断某次跳变必然是数据错误。引擎不会自动增加拆分后的持仓份额；输入未复权日线而忽略份额变化会使回测失真。

## 6. 跨语言比较

除 engine 标签外，递归比较结果的所有字段。数值容差：绝对1e-8、相对1e-10；订单日期、方向、数量、顺序以及每日目标必须一致。发生差异输出 JSON 路径与双方数值，不能用平均两套结果掩盖分歧。

`data_sha256` 对传给引擎的 UTF-8 CSV 原文计算，包括换行符；相同数值、不同 CSV 排版可能有不同指纹。网页完整报告还携带规范化配置的 SHA256 与配置快照。Go 与 Python 都有独立的公式、规则解释、持仓更新、费用和指标统计代码，没有相互调用。

## 7. 自写目标策略

自写 Python 或 Go 策略只替代第 3 节的目标选择步骤，函数输入为当前及过去的原始日线、实际持仓数量、现金和收盘净值，输出下一交易日目标持仓代码。`entry/exit/rank_by/mode` 对自写代码不生效；`universe/benchmark/max_positions/execution/start/end` 仍由同一配置约束并由引擎验证。目标只允许资产池中的不重复代码，最多 `max_positions` 个。缺失当天行情的持仓仍可出现在输入持仓中；不能因为没有新 bar 就伪造成交。第 3–5 节的下一开盘执行、费用、拒单、净值与指标均不改变。代码策略的函数在预热历史日及每个回测日收盘后调用，传入的行情不包含未来日期。
